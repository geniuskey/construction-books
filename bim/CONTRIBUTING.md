# BIMBook 챕터 작성 가이드

BIMBook은 ConstructionBooks 서가(`construction.euiyun.com`)의 여덟 번째이자 마지막 권인 BIM·디지털 건설 교과서다. 배포 주소는 `https://construction.euiyun.com/bim/`. `js/common.js`는 SiteBook 엔진(구조 해석기, `CB.orbit`, 공사 관리 모델 `CB.pm`과 기준 공사 `CB.pm.B10`)을 복사하고 **BIM·디지털 건설 모델** `CB.bim`(결정적 IFC GlobalId, 기준 모델 B-10 BIM 요소 생성기, 상자 겹침과 간섭 검토, 물량 산출, 4 × 4 변환 행렬, 지리 참조, 메시 부피·넓이, 2D 강체 정합, 최소 제곱 평면·RANSAC, 칼만 필터, 작은 IFC STEP 해석기)을 더했다. 본보기는 `../site/chapters/cpm.html`, `../civil/chapters/traffic.html`, `../concrete/chapters/case-study.html`이다.

## 기여물의 라이선스

코드는 MIT, 교재 콘텐츠는 CC BY 4.0. 다른 교재의 문장·그림·연습문제를 옮겨 오지 않는다. 표준·법령·제품·역사적 사실은 확인된 것만 쓴다(확실하지 않으면 "형태", "약", "교육용", "현행 확인"). **특정 상용 소프트웨어를 홍보하거나 사용법을 가르치지 않는다** — 도구에 매이지 않는 원리(데이터 구조, 알고리즘, 프로세스)를 쓰고, 제품 이름은 필요할 때 예시로만 중립적으로 언급한다. 표준(ISO 16739 IFC, ISO 19650, COBie, CityGML 등)은 이름과 확실한 내용만 쓴다.

## 구조

빌드 없이 열리는 정적 페이지. `index.html` + `chapters/<slug>.html` + `css/style.css`(앞 권과 같고 강조색 보라 `#5f3dc4`, 보조색 안전 주황 `#e8590c`) + `js/common.js`(전역 `CB`, `CHAPTERS`). classic script만, 외부 라이브러리 없음(3D는 `CB.orbit` — 이 책은 모델이 주인공이므로 거의 모든 장에서 3D 장면을 쓴다).

- 용어: `js/glossary/<slug>.json`(`{"ko","en","abbr","def","chapters":["<slug>"]}` 배열)에 적고 `tools/merge-glossary.py bim`이 합친다. `en` 대문자 시작, `abbr` 밑줄 금지, 정의에 `<`·`>` 금지, 띄어쓰기 변형 중복 금지. IFC 엔터티 이름(IfcWall 등)은 용어 대신 코드(`<code>`)로 쓴다.

## 원칙: 모델 → 정보 → 협업 → 활용

BIM은 "건물을 짓기 전에 컴퓨터 속에서 한 번 짓고, 그 모델에 담긴 정보를 설계·시공·운영 내내 함께 쓰는" 방법이다. 이 책은 모든 개념을 **모델을 만들고(형상·속성) → 정보를 구조화하고(IFC, LOD, 분류) → 함께 쓰고(CDE, 간섭, 연합) → 활용하는(물량·공정·원가·현장·운영·도시·AI)** 순서로 쓴다. 기준 모델 **B-10 BIM**(앞 권의 B-10을 `CB.bim.model()`로 만든 요소 360개)을 책 전체가 쓴다. 앞 권(구조·재료·시공)의 숫자가 모델 속 속성으로 다시 나타난다.

- 한국어, 대상은 건축·토목 3–4학년과 BIM 실무 입문자. 영어 원어 병기.
- 장 첫머리 `.origin`("이 정보가 없었다면"), 각 절은 가능하면 `.problem`.
- 흐름: 문제 → 그림(SVG) → **조작하는 시뮬레이터**(대개 3D 모델 또는 데이터 표) → 정의·원리(KaTeX가 필요한 곳만) → **손으로 푸는 예제**(`.callout`, 단계별) → 기준 모델 노트(`.callout.site`) → `.uses` → 핵심 정리 → 확인 퀴즈(8문항).
- 정의·원리 `<div class="callout def"><strong>정의 3.2 (속성 세트)</strong> …</div>`, 예제 `예제 3.1`, 그림 `그림 3-1.`, `.callout.deep` 심화.
- 장마다 **시뮬레이터 7–8개, 그림 6개 이상, 퀴즈 8문항.** 계산하는 모델이어야 한다(요소를 끌면 간섭이 다시 검출되고, 속성을 바꾸면 물량·원가가 바뀐다). 극단 입력에도 오류·NaN이 없다. 요소 수백 개를 다루는 계산(간섭, 물량, 점군)은 입력이 바뀔 때만 한다.
- 계산은 `CB.bim`(이 책), `CB.pm`(4D·5D), `CB.frame`/`CB.beam`(구조 분석 연계)으로 한다. 장 고유 모델(속성 검증 규칙, 명명 규칙 검사, 상태 기계, 에너지 간이 모델, 사진 측량 삼각 측량, 철근 가공 최적화, 마르코프 열화, 투영 변환 근사, 유전 알고리즘 등)은 페이지 스크립트에 두고 "교육용"이라 밝힌다.
- 색은 CSS 변수와 `CB.palette()`만. 라이트/다크 모두. 폭 360px 가로 스크롤 금지. SVG는 `viewBox`만, 폭 900 이하.
- 시뮬레이터 `id`는 `sim-<접두사>-<이름>`, 요소 id·전용 CSS 클래스도 접두사. 절 `id`는 의미 있는 영어 슬러그.

## 단위·좌표·색 규약 (책 전체 공통)

**단위.** 길이 m(모델 좌표), 단면 mm(속성), 부피 m³, 넓이 m², 각도 °, 시간 주(4D, SiteBook과 같게), 금액 억 원(5D), 지도 좌표 m(E, N).

**좌표.** 모델 로컬 좌표: 원점 = 격자 A/1 교점, x = 격자 A→E 방향(동쪽에서 θ 회전), y = 1→4, z = 1층 바닥 0에서 위로 +. 층 바닥 높이 0, 5, 9, 13, …, 37 m, 지붕 41 m. 지도 좌표는 `CB.bim.toMap`(가상 기준점, 15장).

**색(3D 장면 공통).** 구조(기둥·보·슬래브) 회색 계열(`text-dim`/`surface-2`), 벽 `accent` 반투명, 덕트 `blue`, 배관 `ok`(초록), 간섭 `bad`(빨강) 강조, 선택 `accent2`(주황) 외곽선, 4D 진행 중 `warn`, 완료 `ok`.

## 기준 모델 B-10 BIM (가상, 교육용)

`CB.bim.model()`이 만드는 요소(지상 1–10층, 지하층·계단·창호·마감은 생략):

| 항목 | 값 |
|---|---|
| 요소 | 총 **360개**: `IfcColumn` 200(층당 20, 800 × 800), `IfcBeam` 90(층당 X 방향 4 + Y 방향 5, 400 × 700 슬래브 포함 춤), `IfcSlab` 10(32.8 × 24.8 × 0.21), `IfcWall` 40(코어 벽 400 mm, 층당 4), `IfcDuctSegment` 10(급기 1,000 × 400, y = 12 m 복도, 중심이 천장 아래 0.55 m), `IfcPipeSegment` 10(스프링클러 φ100, y = 4 m, 바닥판 아래 0.35 m) |
| 속성 | `name`(예: C-A1-1F, G1-X1-1F, DU-SA-3F), `guid`(결정적 22자), `storey`, `level`, `box`, `material`(C30, 아연도 강판, 강관), `props`(단면·두께·시스템 등) |
| 간섭(기본값) | 덕트–보 하드 간섭 **30건**(층당 3: x = 8·16·24 m의 Y 방향 보), 배관–보 **30건**(층당 3), 덕트–코어 벽 **20건**(층당 2, 관통부 — 슬리브·개구부로 해결) |
| 천장고 가정(6장과 공통) | 천장고 = 층고 − (덕트 깊이 + 0.20) − 0.15 m(천장 여유), 바닥 마감 무시. 보 밑 0.05 m 여유 + 목표 2.70 m를 만족하는 덕트 깊이는 0.95 m 하나(2–10층 2.70 m, 1층 3.70 m). 0.90 m부터 하드 간섭 0건(맞닿음) |
| 해결 예 | 덕트를 천장 아래 0.95 m로 내리면(`model({ ductDrop: 0.95 })`) 덕트–보 간섭 0건 — 대신 천장고가 줄어든다(층고 4.0 m − 슬래브·보 0.7 − 덕트) |
| 물량(상자 합) | 기둥 435 m³, 보 500 m³, 슬래브 1,708 m³, 벽 747 m³ → 층당 약 339 m³. SiteBook 12장의 기준층 수량 산출(콘크리트 288.7 m³, 거푸집 약 1,350 m², 철근 34.6 t — `../site/chapters/estimating.html`)보다 크다. 원인은 두 가지: (1) 보·슬래브·벽·기둥이 겹친 부피의 중복 계산 — 우선순위 공제(기둥 > 벽 > 보 > 슬래브, 정확한 상자 합집합)로 전체 131 m³가 빠져 3,259 m³, 기준층 약 322.9 m³; (2) 모델 형상 가정의 차이 — 코어를 닫힌 벽 48 m로 모델링(SiteBook 순 20 m), 슬래브를 기둥 바깥면까지 32.8 × 24.8 m로, 기둥을 보 밑까지 모델링. 즉 공제 후에도 288.7 m³와 같아지지 않으며, 그 차이는 "모델링 규칙이 물량을 정한다"는 7장의 교훈이다 |
| 지리 참조(가상) | 로컬 원점 → E 203,450.000 · N 551,820.000, 회전 12°, 축척 계수 0.99993(교육용, 실제 위치 아님) |
| 4D·5D | 공정은 SiteBook `CB.pm.B10`(93주, BAC 244억). 요소–활동 연결 규칙: 기둥·보·슬래브·벽 1–5층 → G1, 6–10층 → G2, 덕트·배관 → I(설비) |
| 운영(13–14장) | 장 안에서 정의: 공조기·펌프 등 자산 목록, 센서(온도·진동·전력) 시계열은 교육용 생성 데이터 |

**기준 인용.** IFC(ISO 16739-1, buildingSMART), ISO 19650(정보 관리), COBie, IDS(Information Delivery Specification), bSDD, CityGML(OGC), 국내 BIM 지침(예: 국토교통부 건설산업 BIM 기본지침, 조달청 BIM 지침 — 이름과 확실한 내용만, "현행 확인")은 이름으로 인용한다. LOD 체계는 미국 BIMForum LOD Specification 형태와 ISO 19650의 LOIN(정보 요구 수준) 개념을 구분해 쓴다.

**01 BIM의 이해** — 도면 중심에서 모델 중심으로(2D CAD의 한계: 도면 간 불일치, 정보 단절) / BIM의 정의: 형상 + 정보 + 프로세스 / 객체와 속성, 하나의 모델에서 여러 도면 / 생애 주기 활용(기획·설계·시공·운영)과 참여자별 이점 / BIM 성숙도(수준 0–3 형태)와 협업 방식 / 도입 효과와 한계(확인된 연구만, 숫자는 출처 형태 밝힘) / 기준 모델 B-10 BIM과 이 책의 지도. 시뮬: B-10 BIM 3D 탐색(`CB.orbit`: 요소 유형 켜고 끄기, 요소 클릭 → 속성 표, `CB.bim.model`), 하나의 모델 여러 뷰(평면·단면·입면을 같은 요소에서 자동 생성, 단면 높이 끌기), 도면 불일치 실험(2D 도면 두 장에서 기둥 하나만 고치면 생기는 불일치 vs 모델), 속성 질의(조건 입력 → 일치 요소 강조·개수), 생애 주기 정보 흐름(단계 슬라이더 → 정보 누적과 손실 비교, 교육용), 참여자 협업 그물(참여자 수 → 소통 경로 수 n(n−1)/2 vs 중앙 모델), 성숙도 자가 진단(체크 → 수준).
**02 형상 모델링과 파라메트릭** — 좌표계와 단위, 로컬·전역 좌표 / 변환: 이동·회전·축척, 동차 좌표와 4 × 4 행렬(`CB.bim.mat`), 합성 순서 / 형상 표현: 경계 표현(B-rep), CSG, 돌출·회전·스윕, 메시와 삼각형 / 메시 부피·넓이(`meshVolume`, `meshArea`, 발산 정리) / 파라메트릭 모델링: 매개변수와 구속 조건, 패밀리(유형), 의존 관계 / 정밀도와 허용 오차 / B-10 기둥·보를 패밀리로. 시뮬: 변환 행렬 놀이터(이동·회전·축척 슬라이더 → 행렬 값과 3D 상자, 순서 바꾸면 결과 달라짐), 돌출·스윕 만들기(단면 점 끌기 + 경로 → 솔리드, 부피), 메시 부피 계산(상자·각기둥 메시 → 발산 정리 부피와 해석해 비교, 법선 뒤집으면 음수), 파라메트릭 창 패밀리(폭·높이·문틀 매개변수 → 형상 재생성, 구속 위반 경고), 파라메트릭 보(경간 → 춤 = 경간/12 규칙, 그리드 움직이면 보 자동 갱신, B-10 그리드), CSG 불리언(합·차·교 → 결과 부피), 허용 오차와 맞닿음 판정(간격 → 접촉/분리).
**03 IFC와 데이터 모델** — 개방형 BIM과 상호 운용성 / IFC의 구조: 엔터티와 상속(`IfcRoot` → `IfcObject` → `IfcProduct` → `IfcWall` 형태), 관계 엔터티(`IfcRelAggregates`, `IfcRelContainedInSpatialStructure`, `IfcRelDefinesByProperties`), 공간 구조(Project–Site–Building–Storey–Space), 속성 세트(Pset)와 수량 세트, GlobalId(`guid`) / 파일 형식: STEP(ISO 10303-21, `parseStep`), XML·JSON 형태 / MVD와 IDS로 교환 범위 정하기 / 분류 체계(Uniclass·OmniClass 형태, 국내 분류는 확인된 것만) / IFC 버전(2x3, 4 형태) / B-10 BIM을 IFC 그래프로. 시뮬: IFC 공간 구조 트리(B-10: 프로젝트 → 대지 → 건물 → 층 → 요소, 접고 펼치기), STEP 파일 읽기(예제 STEP 텍스트 편집 → `parseStep` → 엔터티 표와 참조 그래프 그림), 상속 계층 탐색(엔터티 클릭 → 상위 속성 상속), 속성 세트 편집(요소 선택 → Pset 값 바꾸기 → 질의 결과 변화), GlobalId 생성(문자열 → 결정적 ID, 같은 객체 = 같은 ID의 의미), IDS 검증(요구 규칙 입력 → B-10 요소 통과/실패 목록, 교육용), 관계 그래프 3D(`CB.orbit`: 요소와 관계 선).
**04 LOD와 정보 요구 사항** — 얼마나 자세히: LOD(형상 상세 + 정보 신뢰도, BIMForum 100–500 형태)와 LOG·LOI, ISO 19650의 LOIN / 단계별 요구 수준 / 발주자 정보 요구 사항(EIR/OIR/AIR 형태)과 BIM 수행 계획(BEP) / 모델 검수: 형상 검사, 속성 완결성, 규칙 기반 검증 / 과잉 모델링의 비용 / B-10 기둥의 LOD 100 → 400. 시뮬: LOD 슬라이더(기둥 하나 LOD 100–400 → 형상 상세·속성 수·파일 크기 증가, 교육용 모델), 단계별 요구 매트릭스(단계 × 요소 → 필요 LOD 칠하기, 과잉·부족 표시), 속성 완결성 검사(B-10 요소 속성 비우기 → 완결성 % 막대), 모델링 노력 vs 가치(LOD → 비용·편익 곡선, 교육용), BEP 체크리스트 생성(프로젝트 특성 → 필요 항목), 검수 규칙 편집기(규칙 추가 → 위반 요소 3D 강조), LOD 400 철근 상세(ConcreteBook G1 배근, `CB.orbit`).
**05 공통 데이터 환경과 정보 관리** — 정보 관리의 필요성 / ISO 19650 개념: 정보 컨테이너, 상태(작업 중 WIP → 공유 Shared → 게시 Published → 보관 Archived), 승인 흐름, 수정 번호 / 명명 규칙(필드 구성 형태)과 메타데이터 / 연합 모델(분야별 모델을 합치기)과 참조 / 버전 관리와 변경 비교(diff), 감사 추적 / 접근 권한과 보안 / 협업 리듬(모델 교환 주기) / B-10 프로젝트의 CDE. 시뮬: CDE 상태 기계(컨테이너를 상태 사이로 끌기 → 허용·거부 전이, 승인자), 명명 규칙 검사기(파일 이름 입력 → 필드별 통과/실패, 교육용 규칙), 모델 버전 비교(두 버전 B-10 → 추가·삭제·변경 요소 색 3D), 연합 모델 조립(구조·건축·설비 모델 켜기 → 간섭 수 변화), 정보 교환 주기 시뮬(주기 → 재작업량·간섭 발견 지연, 교육용), 접근 권한 매트릭스(역할 × 상태 → 읽기/쓰기), 감사 추적 타임라인.
**06 간섭 검토** — 간섭의 종류: 하드(물리적 겹침), 소프트(유지 공간·여유 거리), 4D(시간 간섭), 워크플로 간섭 / 판정 알고리즘: 경계 상자(AABB) 겹침(`overlap`), 침투 깊이·겹침 부피, 허용 오차, 분할(격자)로 빠르게 / 간섭 그룹과 규칙(덕트–보, 배관–보, 덕트–벽 관통) / 중복·허위 간섭 걸러내기, 우선순위 / 해결 워크플로(담당·상태·재검토) / 해결 방법: 경로 변경·높이 조정·보 관통 슬리브·개구부 / B-10: 덕트–보 30건, 배관–보 30건, 덕트–코어 벽 20건(`clashes`). 시뮬: 간섭 검토기(그룹 고르기·허용 오차 슬라이더 → 간섭 목록·3D 빨강 강조, `CB.bim.clashes`), 덕트 높이 조정(덕트 내리기 → 간섭 수와 천장고 trade-off 곡선, `model({ ductDrop })`), AABB 겹침 놀이터(두 상자 끌기 → 겹침 축·깊이·부피), 소프트 간섭 여유 공간(유지보수 공간 두께 → 추가 간섭), 간섭 그룹화(근접 간섭 묶기 → 해결 단위 수), 간섭 해결 워크플로 보드(상태 칸반, 재검토 주기 → 남은 간섭 곡선), 격자 가속(요소 수 → 비교 횟수 n² vs 격자, 계산 시간).
**07 모델 기반 물량 산출** — 모델에서 물량을 꺼내는 원리(객체·속성·기하) / 물량 산출 규칙: 측정 단위, 공제(겹친 부피), 우선순위(기둥 > 보 > 슬래브 형태), 개구부 공제 기준 / 모델 품질과 물량 정확도(LOD 연결) / 분류 코드와 내역 연결(공종별 집계) / 2D 수작업 적산과 비교, 오차 원인 / B-10: 상자 합 층당 339 m³ → 공제 후 약 322.9 m³ vs SiteBook 288.7 m³(남는 차이는 모델 형상 가정)(`qto` + 페이지 공제 알고리즘). 시뮬: 물량 집계 표(B-10 요소 → 유형별 개수·부피·넓이, `CB.bim.qto`, 층 필터), 겹침 공제 실험(우선순위 규칙 바꾸기 → 공제량·총 부피, 상자 교집합 계산), 거푸집 면적 산출(접촉면 제외 → 거푸집 면적, SiteBook 12장 약 1,350 m²/층과 비교), 철근 물량(콘크리트 부피 × 철근 비 vs 상세 모델, 교육용), 개구부 공제 기준(개구부 크기 → 공제 여부), 내역 연결(분류 코드 → 공종별 금액 막대, SiteBook 원가 연결), 2D vs BIM 적산 오차(도면 오류 주입 → 물량 차이).
**08 모델 기반 설계 분석** — 하나의 모델, 여러 분석 / 구조 분석 모델로 변환: 물리 모델 → 해석 모델(축선·절점·지점), `CB.frame`으로 B-10 골조 한 줄 해석(StructureBook·MechanicsBook 연결) / 에너지·일조: 외피 면적·창면적비·열관류율(MaterialsBook 15장), 간이 냉난방 부하(교육용), 태양 위치와 그림자 / 피난: 보행 거리, 출구 용량(교육용 간이 모델) / 규정 자동 검토(규칙 → 위반 목록, 천장고·통로 폭 예) / 분석 결과를 모델로 되돌리기 / 상호 운용의 손실. 시뮬: 물리 → 해석 모델 변환(B-10 기둥·보 상자 → 축선·절점, `CB.frame` 해석 → 변형 3D), 창면적비와 에너지(창 비율 슬라이더 → 열 손실·일사 취득, 교육용 정상 상태 모델), 태양 경로와 그림자(날짜·시각 → 그림자 투영, 위도 37.5° 가정, 교육용 태양 위치 식), 피난 거리 검사(출구 위치 끌기 → 층 평면 최대 보행 거리, 격자 거리장), 천장고 규정 검사(덕트 높이 → 천장고 → 기준 형태 판정), 분석 연계 손실(교환 단계 → 남는 정보 %, 교육용), 규칙 기반 검토 편집기.
**09 4D 공정 시뮬레이션** — 4D = 모델 + 공정 / 요소–활동 연결 규칙(B-10: 1–5층 → G1, 6–10층 → G2, 설비 → I), 작업 분류와 모델 분할 / 시공 순서 시뮬레이션(`CB.pm.cpm`의 ES 기준 주 슬라이더) / 4D로 찾는 문제: 순서 오류, 작업 공간 충돌, 양중 경로 / 계획 대 실적 비교와 진도 시각화 / 가설·장비 4D / SiteBook 9·13장 연결. 시뮬: 4D 재생(주 슬라이더·재생 → 요소가 공정에 따라 나타남, 진행 중 주황·완료 초록, `CB.pm.cpm(CB.pm.B10)` + `CB.bim.model`), 연결 규칙 편집(요소 유형·층 → 활동 매핑 바꾸기 → 연결 안 된 요소 경고), 공정 변경 영향(활동 기간 바꾸기 → 4D 즉시 갱신), 작업 공간 간섭(활동별 작업 공간 상자 → 같은 시기 겹침 검출), 계획 대 실적(SiteBook 13장 지연 시나리오 → 늦은 요소 빨강), 층별 진도 히트맵(주 → 층 × 공종 진도), 타워크레인 양중 시퀀스(요소 무게·반경 → 양중 순서 3D).
**10 5D 원가와 디지털 견적** — 5D = 모델 + 물량 + 단가 / 단가 연결(일위대가, SiteBook 12장) / 설계 변경의 원가 영향(모델 바꾸면 물량·금액 자동 갱신) / 시간에 따른 원가(4D + 5D = 현금 흐름, SiteBook `spread`) / 대안 비교(단면·재료 바꾸기) / 기성 산정과 진도 측정 / 정확도와 한계 / B-10 골조 원가. 시뮬: 5D 계산기(B-10 요소 물량 × 단가 → 공종별 금액, 단가 편집, 층 필터), 설계 변경 원가 델타(기둥 단면·슬래브 두께 바꾸기 → 물량·금액 변화), 4D + 5D 현금 흐름(요소 완료 시점 × 금액 → S 곡선, `CB.pm.spread`와 비교), 대안 비교(RC vs 철골 프레임 → 물량·원가·공기, StructureBook·SiteBook 연결, 교육용), 기성 산정(주 → 완료 요소 금액 = 기성), 원가 3D 히트맵(요소를 금액으로 색칠), 단가 민감도(토네이도).
**11 현실 캡처: 측량·드론·스캔** — 측량 좌표와 기준점 / 지리 참조(`toMap`, `toLocal`) / 사진 측량: 중복 촬영, 삼각 측량 원리(교육용 2D), 지상 표본 거리 / 레이저 스캔과 점군: 거리·각도 → 좌표, 점 밀도, 노이즈 / 정합: 대응점 강체 변환(`rigid2D`), ICP 맛보기 / 평면 추출: 최소 제곱(`planeFit`), RANSAC(`ransacPlane`) / 스캔 대 BIM 편차 분석(as-built 검증) / 드론 토량(SiteBook 16장 연결) / B-10 슬래브 평탄도 검사. 시뮬: 측량 좌표 변환(로컬 점 끌기 → 지도 좌표, 회전·축척 매개변수, `toMap`), 사진 측량 삼각 측량(두 카메라 위치·각도 → 점 위치와 오차, 교육용 2D), 점군 정합(두 점군 끌어 맞추기 vs 자동 `rigid2D`, RMS), RANSAC 평면(잡음·이상점 비율 → 찾은 평면·inlier 수, 최소 제곱만 쓰면 기울어짐 비교, `ransacPlane`·`planeFit`), 슬래브 평탄도 히트맵(합성 점군 → 평면 편차 색, 허용 기준 형태), 스캔 대 BIM 편차(시공 기둥 위치 오차 → 편차 색 3D), 점 밀도와 거리(스캐너 각도 분해능·거리 → 점 간격).
**12 디지털 제작과 프리패브** — DfMA 원리 / 모델에서 제작 데이터로: 철근 가공(형상 코드·절단·굽힘), 철골 상세와 CNC, 덕트·배관 스풀 / 철근 절단 최적화(1차원 절단 재고 문제, SiteBook 6장 연결) / 모듈러·프리캐스트 분할과 운송 제약(StructureBook 13장, SiteBook 7장) / 허용 오차 누적과 조립 / 로봇·자동화 맛보기 / 디지털 제작의 품질 추적(ID와 QR) / B-10 G1 철근 가공표. 시뮬: 철근 가공표 생성(G1 배근 → 형상·길이·개수, ConcreteBook 연결), 절단 최적화(필요 길이 목록 → 12 m 원재료 배치, FFD vs 단순 → 손실률), 모듈 분할(B-10 층을 모듈 크기로 나누기 → 모듈 수·운송 제약 판정), 공차 누적(부재 수·개별 공차 → 누적 편차 분포, 최악 vs 통계), 덕트 스풀 분할(덕트 길이·운반 길이 → 스풀 수·이음 수), CNC 절단 경로(부재 구멍 위치 → 공구 경로 길이, 교육용 최근접), 조립 순서 3D(`CB.orbit`).

## JS 헬퍼 (`js/common.js`, 전역 `CB`)

화면·컨트롤·차트·좌표 평면·3D·구조 해석은 `../mechanics/CONTRIBUTING.md`의 "JS 헬퍼"와 같다(`CB.canvas`, `CB.chart`, `CB.plane`, `CB.orbit`, `CB.range`, `CB.seg`, `CB.loop`, `CB.normCdf`, `CB.rng`, `CB.histogram`, `CB.mean`, `CB.std`, `CB.beam`, `CB.frame` …). 공사 관리 `CB.pm`(CPM·spread·EVM, 기준 공사 `CB.pm.B10`)은 `../site/CONTRIBUTING.md`의 "JS 헬퍼"와 같다. 시그니처는 반드시 `js/common.js` 소스에서 확인한다. 3D 장면은 `CB.orbit`으로 그리고, 요소 상자 하나는 직육면체 모서리 12개(또는 면 6개)로 그린다. 요소 360개를 매 프레임 그리는 것은 괜찮지만, 간섭·물량·점군 계산은 입력이 바뀔 때만 한다.

BIM·디지털 건설(이 책에서 더함):

```js
const els = CB.bim.model({ floors: 10, ductDrop: 0.55, pipeDrop: 0.35 });
// [{ id, guid, ifc: "IfcColumn" | "IfcBeam" | "IfcSlab" | "IfcWall" | "IfcDuctSegment" | "IfcPipeSegment",
//    name: "C-A1-1F", storey: 1, level: 0, box: [x0, y0, z0, x1, y1, z1], material: "C30", props: { section, ... } }]  — 기본 360개
CB.bim.guid("seed");                       // 결정적 22자 IFC GlobalId (같은 seed → 같은 ID)
CB.bim.overlap(boxA, boxB, tol);           // { hard, soft, depth (침투 깊이, 떨어져 있으면 −간격), volume, gap }
CB.bim.clashes(els, ["IfcDuctSegment"], ["IfcBeam"], tol);   // [{ a, b, type: "hard" | "soft", depth, volume, center: [x, y, z] }]
CB.bim.qto(els);                           // { IfcColumn: { count, volume }, ... } (상자 부피 합 — 공제 없음)
const M = CB.bim.mat;                      // I(), T(x, y, z), Rz(deg), S(k), mul(A, B), apply(M, [x, y, z]) — 4 × 4 동차 행렬
CB.bim.GEO;                                // { E0: 203450, N0: 551820, theta: 12, s: 0.99993 } (가상)
CB.bim.toMap(x, y, g); CB.bim.toLocal(E, N, g);   // 2D 헬머트 지리 참조와 역변환
CB.bim.boxMesh(box);                       // { V: [[x, y, z]×8], F: [[i, j, k]×12] } 바깥 법선
CB.bim.meshVolume(V, F); CB.bim.meshArea(V, F);   // 발산 정리 부피(닫힌 메시), 겉넓이
CB.bim.rigid2D(P, Q);                      // 대응점 [[x, y]] → { theta (°), tx, ty, rms }  (Q ≈ R P + t)
CB.bim.planeFit(pts);                      // [[x, y, z]] → { n (단위 법선), d (n·x = d), rms, centroid }
CB.bim.ransacPlane(pts, iters, tol, seed); // { ok, n, d, rms, inliers }
CB.bim.kalman1D(z, q, r, x0, P0);          // { x: [추정], P: [오차 분산] }
CB.bim.parseStep(text);                    // { 12: { type: "IFCWALL", args: ["'2O2Fr$t4X7Zf8NOew3FLOH'", "#5", ...], refs: [5, ...] } }
CB.bim.jacobi;                             // 3 × 3 대칭 행렬 고유값 분해(planeFit 내부)
```

`boxMesh`의 반환 모양과 `rigid2D`·`kalman1D`의 기본값은 소스에서 확인한다. `CB.bim`을 고쳤으면 `node tools/bim.test.cjs`(`npm test`에 포함)를 다시 돌린다. 엔진에 없는 기능이 필요하면 페이지 스크립트에 작은 함수로 쓰고, 여러 장에 필요해 보이면 보고서에 적는다(엔진은 직접 고치지 않는다).

소스에는 `<title>`과 `<meta name="description">`(한 줄)만 쓴다. canonical·Open Graph 태그는 `tools/build.mjs`가 `bim/book.json`의 `meta`로 생성하고, 수식은 빌드가 `tools/katex.mjs`로 미리 렌더링한다. 그래서 다음을 지킨다. 어기면 `npm test`나 빌드가 실패한다.

- canonical·`og:` 태그, KaTeX `<link>`/`<script>`를 소스에 넣지 않는다.
- **스크립트가 수식을 DOM에 넣지 않는다.** 인라인 `<script>` 안에 `\(`·`\[`·`$$`가 있으면 검사가 실패한다. 시뮬레이터의 식 출력은 HTML(`<sup>`, `<sub>`, `·`, `−`, `√`, `∑`)로 만든다.
- 수식 안에서 `<` 바로 뒤에 글자가 오면 브라우저가 태그로 읽는다. `a<b` 대신 `a \lt b` 또는 `a < b`(공백).
- 수식 안의 HTML 엔티티는 `&amp; &lt; &gt; &nbsp; &middot; &times; &minus;`와 숫자 엔티티만 쓴다.
- **`\text{…}` 안에 가운뎃점 `·`을 쓰지 않는다**(KaTeX가 `\cdotp` 오류를 낸다). 곱은 `\text{}` 밖에서 `\cdot`, 나열은 쉼표.
